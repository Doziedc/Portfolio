HistoBuddy

Learn History Through Adventure

The Problem

Nigerian history often feels distant and boring when taught in class. HistoBuddy turns it into an adventure, so learning feels like an experience, not a lesson.

Who It's For

Children learning Nigerian history, who need history to feel fun and alive rather than like a textbook. Because the users are children, the design keeps things simple, playful, and easy to tap through without adult help.

User Flow

Here's how a child moves through the app, from sign-up to finishing a lesson.

Wireframe to Final Design

Before adding colors and images, I laid out the structure of all 6 screens in wireframes, then built on top of that same structure for the final design.

Wireframes

Final Design

The gray placeholder boxes became warm, clay-textured illustrations featuring a recurring character, giving the app a crafted, adventure-like feel instead of a generic app look. "Continue with Email" and other key actions became a bold, consistent purple, so users always know the next step. Even with this full visual redesign, the screen order, layout, and information structure stayed exactly as planned in the wireframes, proving the original structure held up through a complete style change.

Design Choices

  • A consistent character guide instead of generic illustrations. A small recurring character appears across all 6 screens, acting like a "buddy" to learn alongside, which fits the HistoBuddy name and makes history feel like a guided adventure for a child.
  • Warm, sandy, clay-like tones instead of flat cartoon colors. The textured, earthy illustration style feels tied to history and discovery, making learning feel like exploring something real and exciting, not like sitting in a classroom.
  • One consistent accent color (deep purple/indigo). Every primary action uses the same color, so a child always knows what to tap next without guessing.
  • "Continue as a Guest" still kept. Children often don't have their own email, so this option removes that barrier completely.
  • Category pills and card layout kept from the original wireframe, proving the original structure was solid enough to carry through a full visual redesign.
  • Progress and rewards made visible. XP, streaks, and a progress bar turn finishing a lesson into a small win, which helps keep a child motivated to come back.

Doz Motors

A premium car dealership website, built from scratch with HTML, CSS, and JavaScript

Overview

Doz Motors is a concept car dealership site built to practice real front-end development: structuring a multi-section layout, building reusable card components, and using JavaScript to let users filter a product grid without reloading the page.

My Role & Tools

I designed and built this project alone, from layout to logic, structuring the homepage and the car listings page, then writing the JavaScript that powers the category filtering.

HTML CSS JavaScript

Structure

The site is split into two pages:

  • Home: A hero section, a short preview of featured cars, and a trust-building section about the inspection and warranty process.
  • Cars: The full collection, with filter buttons (All, Sports, SUV, Saloon, Electric) that instantly show or hide cars by category.

The Filtering Logic

Each car card carries a hidden label (a data-category attribute) marking its type, and each filter button carries a matching label of its own. When a button is clicked, JavaScript compares the two labels: if they match, or if "All" is selected, the card stays visible; otherwise it's hidden. This was the trickiest part of the build, since it meant thinking through the logic before writing any code, not just styling what was already there.

Images

Two of the car photos (the Sports and SUV models) are real stock-style photography. The remaining two (Saloon and Electric) were AI-generated to match the same photographic style, since real photography wasn't available for every category needed to demonstrate the filter working across all four types.

Habit Tracker

A clean, dark-mode web app for building and tracking daily habits

Overview

Habit Tracker is a fully functional web application designed to help users build daily routines. It goes beyond a simple to-do list by implementing real streak logic and persistent data storage, so users never lose their progress even if they close the browser.

My Role & Tools

I designed and built the entire application from scratch. This project was a deep dive into state management, local storage persistence, and building a clean, usable dark-mode interface.

Next.js TypeScript Tailwind CSS localStorage

Key Features

  • Full CRUD Functionality: Users can create, read, update, and delete habits instantly.
  • Streak Logic: The app tracks consecutive days of completion, motivating users to maintain momentum.
  • Persistence: All data is saved to the browser's localStorage, meaning habits survive page refreshes and browser restarts.
  • Dark-Mode UI: A sleek, eye-friendly interface built entirely with Tailwind CSS.

Movie Night

A fast, responsive movie search application powered by the TMDB API

Overview

Movie Night is a search engine for films. The goal of this project was to master API integration and handle real-world edge cases—like network errors, empty results, and loading delays—in a way that feels smooth and professional to the user.

My Role & Tools

I built the front-end architecture, integrated the TMDB API, and implemented UI state management for various loading and error scenarios.

Next.js TypeScript Tailwind CSS TMDB API

Key Features

  • Debounced Search: Input is debounced to prevent spamming the API on every keystroke, improving performance and user experience.
  • Pagination: Results are paginated, allowing users to browse through hundreds of movies without overwhelming the page.
  • Full State Management: Handles loading spinners, empty search results, and API errors gracefully.
  • Responsive Design: A movie-poster grid that adapts beautifully to any screen size.
